# Tags and Releases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every repository gets a version bump on pull requests, releases cut by a button or MCP tool from what landed
since the last release, a changelog (the release list), and a Tags view.

**Architecture:** Pure version arithmetic in `worker/src/lib/semver.ts`; D1 tables `releases` and `release_pulls` plus
`pull_requests.version_bump`; `worker/src/lib/releases.ts` computes the unreleased set from D1 alone and cuts a
release (lightweight tag via Artifacts, compare-and-swap from absent, then the row, then `onRefsUpdated`); a
Zod-OpenAPI router and two MCP tools call it; the SPA gets a Releases tab, a Tags view and the bump control.

**Tech Stack:** Hono + Zod-OpenAPI, Drizzle/D1, Cloudflare Artifacts (via `GitService`), React + TanStack Query,
Vitest in workerd (`@cloudflare/vitest-pool-workers`).

**Spec:** `docs/superpowers/specs/2026-10-20-releases-design.md`

## Global Constraints

- Bump values exactly `major` | `minor` | `patch`; a landed PR with none counts as `patch`, shown as "patch (default)".
- Version tags are plain `vX.Y.Z` (no pre-release, no build metadata).
- Unreleased = merged PRs whose `landTargetOf(pr)` is the repository's current default branch and which are in no
  `release_pulls` row. D1 only, never a history walk.
- A tag is created only from absent (`old = ZERO_SHA`); an existing tag is never moved.
- Releases cannot be deleted; versions are never reused. Only title and notes are editable.
- First release: version must be typed (suggest `v0.1.0`), notes default `First release.`, every PR in the unreleased
  set is recorded in its `release_pulls` but not listed.
- Later releases: next version = latest release with the largest unreleased bump applied (`major` → `X+1.0.0`,
  `minor` → `X.Y+1.0`, `patch` → `X.Y.Z+1`).
- Computed version whose tag already exists → 409 naming the tag, asking for a typed version. Never skip ahead.
- An override must parse as `vX.Y.Z`, be greater than the latest release, and have no existing tag.
- Who may cut: push access (`permissionsFor(...).write`). Cutting takes `headSha`; a moved default branch → 409 with the
  new head.
- Hand-pushed version tags are not releases and never count as "latest release".
- Notes: grouped `### Major`, `### Minor`, `### Patch` (empty groups omitted), one line per PR
  `- <title> (#<n>) @<author login>`, then `Full changes: <origin>/<owner>/<repo>/compare/<previous tag>...<new tag>`.
- Never hand-write migrations (`yarn db:generate`). Never mock `env.DB`; use the Artifacts fake. `yarn` only.
- Every mutation calls `recordAudit` (new actions below). Live pings come from the existing `pingAfterChange`
  middleware for REST; MCP paths ping as existing MCP mutations do.
- Definition of done per task: its tests pass; at the end `yarn test`, `yarn typecheck`, `yarn format`.

## Review Focus

1. Two people cut a release at the same moment: exactly one succeeds; the other gets 409 (tag CAS, unique
   `(repository_id, tag)`), and no orphan row or orphan tag remains. → Task 3 test "concurrent cuts".
2. The tag push succeeds but the D1 write fails: retrying must not fail forever on "tag exists". → Task 3: when the tag
   already points at the same commit the caller is releasing and no `releases` row has that tag, the cut adopts it
   (test "retry after a half-finished cut").
3. A PR merged into a non-default branch (stacked or retargeted) must not appear as unreleased. → Task 3 test.
4. The default branch is renamed in settings between releases: unreleased follows the new default branch; PRs that
   landed on the old name stay out. → Task 3 test.
5. A repository with Actions on and a workflow `on: push: tags: ['v*']`: cutting queues exactly one run with
   `ref = refs/tags/vX.Y.Z`. → Task 3 test (with `crewRepo({ actions: true })`).

### Task 3: Tags, unreleased changes, cutting a release

**Files:**

- Test: `worker/src/__tests__/releases.test.ts`

**Interfaces:**

- Consumes: Task 1; Task 2 tables; `onRefsUpdated(env, db, repo, repoFullName, updates, actorId)` from
  `actions/trigger.ts`; `landTargetOf`; `gitFor`; `recordAudit`; `GitPushError`, `ZERO_SHA` from `git/remote`.
- Produces:
  - `GitService.createRef(ref: string, sha: string): Promise<void>` — push with `old: ZERO_SHA` always; throws
    `GitPushError` if the ref exists.
  - `GitService.tags(): Promise<{ name: string; sha: string }[]>` — from `refs()`, `refs/tags/*` only, peeled to the
    commit when the advertisement has `^{}`; sorted by name descending.
  - `type UnreleasedPull = { number: number; title: string; author: string; bump: Bump | null; mergedAt: number }`
  - `unreleased(db, repo, origin: string, repoFullName: string): Promise<{ pulls: UnreleasedPull[]; latest: ReleaseRow | null; next: string | null; notesPreview: string }>` —
    `next` null when there is no release yet (first release must be typed) or `pulls` is empty.
  - `releaseNotes(pulls: UnreleasedPull[], links: { compareUrl: string | null }): string`
  - `cutRelease(opts: { env; db; repo; repoFullName; origin: string; actor: { id: string; via?: string | null };
headSha: string; version?: string; title?: string; notes?: string }): Promise<CutResult>` where
    `CutResult = { ok: true; release: ReleaseView } | { ok: false; status: 400 | 403 | 409; message: string; head?: string }`
  - `listReleases(db, repo): Promise<ReleaseView[]>` (newest first by version), `getRelease(db, repo, tag)`,
    `updateRelease(db, repo, tag, patch: { title?: string; notes?: string }, actor)`.
  - `type ReleaseView = { tag: string; title: string; notes: string; commitSha: string; createdAt: number; createdBy:
string | null; pulls: { number: number; title: string; bump: Bump | null }[] }`
  - `releasedIn(db, pullRequestId): Promise<string | null>` for Task 2's `releasedIn` field.

`cutRelease` order (the spec's section 3): resolve default branch head → 409 with `head` if ≠ `headSha`; compute or
validate version; refuse empty unreleased set (409 `Nothing to release`); `createRef('refs/tags/' + tag, headSha)`
(on `GitPushError`: if the tag already points at `headSha` and no `releases` row has it, continue — Review Focus 2;
else 409 `Tag <tag> already exists; type a version`); insert `releases` + `release_pulls` in one `db.batch` (unique
violation → 409); `onRefsUpdated` with `{ ref, old: ZERO_SHA, new: headSha }`; `recordAudit('release.created')`.

    `- <title> (#<n>) @octocat`, and `Full changes: …/compare/v0.1.0...v0.2.0`.
  - "missing bump counts as patch": only null bumps → `next` `v0.2.1` after `v0.2.0`.
  - "override must be greater and free": `v0.1.0` after `v0.2.0` → 400; `v1.0.0` → ok.
  - "a hand-pushed tag blocks the computed version": push `refs/tags/v0.3.0` through the fake, computed `v0.3.0` →

  - "a moved default branch is 409 with the new head".
  - "nothing to release is 409".
  - "a PR into another branch is not unreleased" (Review Focus 3).
  - "renaming the default branch" (Review Focus 4): set `default_branch` to a new branch; PRs landed on the old name
    are not unreleased.
  - "concurrent cuts" (Review Focus 1): two `cutRelease` calls with the same input in `Promise.all` → one ok, one 409;

  - "retry after a half-finished cut" (Review Focus 2): create the tag at head first via `createRef`, then cut the

  - "the tag queues push runs" (Review Focus 5): `crewRepo({ actions: true })`, a workflow file with

  - "contents freeze": after a cut, land another PR → the release's `pulls` unchanged; `releasedIn` of an old PR is the
    tag, of the new one null.
  - "tags lists every tag, hand-pushed too", sorted by name descending.
