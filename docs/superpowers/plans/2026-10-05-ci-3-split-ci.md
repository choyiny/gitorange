# Split CI by Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitOrange's own CI builds and typechecks once, then runs the tests split by module in parallel jobs, each gated by `gitorange/relevance@v1` on GitOrange and always run on GitHub; a test proves every test file belongs to exactly one module and that the workflow parses with GitOrange's own parser.

**Architecture:** `.github/workflows/ci.yml` gets a `build` job (install, build, typecheck, cache `node_modules` + `dist/` keyed by the commit, plus the module-coverage check), a `gate` job (the relevance action, skipped on GitHub), and one `test-<module>` job per module (`needs: [build, gate]`, the spec's `if:`, restore the commit's cache, `yarn test <its files>`). `worker/src/__tests__/ci-workflow.test.ts` reads `ci.yml` with `?raw`, lists every test file with Vite's `import.meta.glob`, and checks the file↔module mapping, the gate↔job wiring, and the `if:` semantics with GitOrange's own `parseWorkflow`, `planJobs`, `parseRelevanceInputs`, and `evaluateCondition`.

**Tech Stack:** GitHub Actions workflow syntax (run by GitOrange Actions and GitHub), Vitest in workerd with Vite transforms (`?raw`, `import.meta.glob`).

**Spec:** `docs/superpowers/specs/2026-10-05-ci-relevance-design.md` (section 3; Testing: "CI file").

**Depends on:** the job-queue plan and the relevance plan (`2026-10-05-ci-1-job-queue.md`, `2026-10-05-ci-2-relevance-action.md`) being merged: the workflow uses `gitorange/relevance@v1`, and the test uses `parseRelevanceInputs`.

## Global Constraints

- `build`: checkout, setup-node (with its `node_modules` cache), install, stage `wrangler.jsonc`/`.dev.vars`, build, typecheck; save `node_modules` and `dist/` with `actions/cache` keyed by the commit.
- `gate`: runs `gitorange/relevance@v1` with the module list; its job-level `if:` is false on GitHub (`github.server_url != 'https://github.com'`).
- One test job per module, each `needs: [build, gate]`, with `if: always() && needs.build.result == 'success' && (needs.gate.result == 'skipped' || needs.gate.outputs.run-<m> == 'true')`, restoring the commit's cache and running `yarn test <its files>`.
- Modules (by test file): stacking (`stacking`, `stack-tree`, `land-target`), review and states (`review`, `review-diagram`, `pull-states`), merge and conflicts (`merge-resolution`, `pulls-ai-resolution`, `git-merge`, `squash-credits`), Actions (`actions`, `actions-syntax`, `cron`), MCP (`mcp`), git and LFS (`git-http`, `git-objects`, `lfs`, `raw-files`), core (`repos-pulls`, `setup-invites`, `teams-visibility`, `admin-setup`, `settings`, `commit-emails`, `smoke`, `live`, `usage`, `insights`, `ai-gateway`), UI libraries (`src/lib/**/*.test.ts`).
- A test file not assigned to a module fails a check in CI.
- Project rules (CLAUDE.md): `yarn` only; done = `yarn test`, `yarn typecheck`, `yarn format`. This workflow never deploys.

## Decisions

- **Test files as of `main` today, plus the earlier plans.** On `main` (27 files): `actions-syntax`, `actions`, `admin-setup`, `ai-gateway`, `commit-emails`, `cron`, `git-http`, `git-merge`, `git-objects`, `insights`, `lfs`, `live`, `mcp`, `merge-resolution`, `pulls-ai-resolution`, `raw-files`, `repos-pulls`, `review-diagram`, `review`, `settings`, `setup-invites`, `smoke`, `squash-credits`, `stack-tree`, `stacking`, `teams-visibility`, `usage`, and `src/lib/{agentPrompt,highlight,repoUrls,stackTree}.test.ts`. The two earlier plans add `actions-queue` and `actions-relevance` (module `actions`); this plan adds `ci-workflow`. `land-target` and `pull-states` are on unmerged branches: **whoever merges those branches adds them to `test-stacking` and `test-review` respectively**, and the coverage test fails until they do (that's its job). Before Task 1, run `ls worker/src/__tests__/*.test.ts src/lib/**/*.test.ts` and put any other new file into its spec module.
- **The coverage check runs in `build`, not in a module.** If it lived in a module job, the gate could skip it exactly when a pull request adds an unassigned test file. `build` always runs, so it runs `yarn test worker/src/__tests__/ci-workflow.test.ts` after typechecking; the coverage test counts that step as the file's one home.
- **Module names:** `stacking`, `review`, `merge`, `actions`, `mcp`, `git`, `core`, `ui`; job ids `test-<name>`.
- **Extra always-run paths** for this repository: `worker/src/__tests__/helpers/**`, `worker/test/**` (test setup every file uses), `worker/src/db/**`, and `migrations/**` (the schema every test runs against).
- **A cache miss doesn't fail a module:** each module job builds itself when `actions/cache` reports no exact hit.
- **`always()` as the spec says.** GitHub's `cancel-in-progress` still stops these jobs before they start when `build` is cancelled, because `needs.build.result == 'success'` is false.

## Review Focus

- **A pull request that adds a test file and doesn't assign it** — CI must fail on that pull request, even when Clef would skip every module. Pinned by "every test file belongs to exactly one module" running in `build` (Task 1, and the workflow test that `build` runs the check).
- **A module listed in the gate without a job, or a job without a gate output** — modules silently never run, or always skip. Pinned by "the gate, its outputs, and the module jobs agree" (Task 1).
- **The build cache missing in a module job** — the job must build instead of failing. Pinned by "module jobs restore the commit's build, and build it on a miss" (Task 1).
- **CI on GitHub** (the gate skipped) — every module must run. Pinned by "each module's if: runs on GitHub, follows the gate on GitOrange, and never runs after a failed build" (Task 1).
- **A stale entry** (a file renamed or deleted but still listed) — `yarn test` would quietly match nothing. Pinned by "every listed test file exists" (Task 1).

```ts
import { describe, expect, it } from 'vitest';
import ciText from '../../../.github/workflows/ci.yml?raw';
import { evaluateCondition, type Value } from '../actions/expressions';
import { planJobs } from '../actions/plan';
import { parseRelevanceInputs } from '../actions/relevance';
import { githubContext } from '../actions/trigger';
import { parseWorkflow, type JobDef } from '../actions/workflow-file';

/**
 * GitOrange's own CI (.github/workflows/ci.yml) runs the tests split by module. These checks keep
 * that split honest: every test file runs in exactly one place, and the gate's wiring is right.
 */

/** Every file vitest runs (worker/vitest.config.ts `include`), from the repository root. Lazy: nothing is imported. */
const TEST_FILES = Object.keys({
  ...import.meta.glob('./*.test.ts'),
  ...import.meta.glob('../../../src/lib/**/*.test.ts'),
})
  .map((p) =>
    p.startsWith('./')
      ? `worker/src/__tests__/${p.slice(2)}`
      : p.replace(/^(\.\.\/)+/, '')
  )
  .sort();

const wf = parseWorkflow(ciText);
const job = (key: string) => {
  const j = wf.jobs.find((x) => x.key === key);
  if (!j) throw new Error(`ci.yml has no job ${key}`);
  return j;
};
const gate = job('gate');
const gateStep = gate.steps.find((s) => s.uses === 'gitorange/relevance@v1')!;
const modules = parseRelevanceInputs(gateStep.with).modules.map((m) => m.name);
const testJobs = wf.jobs.filter((j) => j.key.startsWith('test-'));

/** The arguments of every `yarn test …` step in a job. */
function filters(j: JobDef): string[] {
  return j.steps
    .filter((s) => s.run?.trim().startsWith('yarn test'))
    .flatMap((s) => s.run!.trim().split(/\s+/).slice(2));
}
/** A filter is a file path, or a directory ending in `/` that covers everything under it. */
const covers = (filter: string, file: string) =>
  filter.endsWith('/') ? file.startsWith(filter) : filter === file;

const moduleIf = (m: string) =>
  `always() && needs.build.result == 'success' && (needs.gate.result == 'skipped' || needs.gate.outputs.run-${m} == 'true')`;

describe('CI workflow (.github/workflows/ci.yml)', () => {
  it('parses and plans with GitOrange Actions', () => {
    const github = githubContext('octocat/gitorange', {
      event: 'pull_request',
      ref: 'refs/pull/1/head',
      headSha: 'a'.repeat(40),
    }) as Record<string, Value>;
    const planned = planJobs(wf, github);
    expect(planned.map((j) => j.key)).toEqual([
      'build',
      'gate',
      ...modules.map((m) => `test-${m}`),
    ]);
  });

  it('sees the test files (import.meta.glob works here)', () => {
    expect(TEST_FILES.length).toBeGreaterThan(25);
    expect(TEST_FILES).toContain('worker/src/__tests__/ci-workflow.test.ts');
    expect(TEST_FILES.some((f) => f.startsWith('src/lib/'))).toBe(true);
  });

  it('every test file belongs to exactly one module', () => {
    const homes = (file: string) =>
      wf.jobs
        .filter((j) => filters(j).some((f) => covers(f, file)))
        .map((j) => j.key);
    const wrong = TEST_FILES.map((f) => ({ file: f, jobs: homes(f) })).filter(
      (x) => x.jobs.length !== 1
    );
    // A new test file? Add it to the `yarn test` line of its module's job in ci.yml.
    expect(wrong).toEqual([]);
  });

  it('every listed test file exists', () => {
    const stale = wf.jobs
      .flatMap((j) => filters(j))
      .filter((f) => !TEST_FILES.some((file) => covers(f, file)));
    expect(stale).toEqual([]);
  });

  it('build checks the module split itself, so the gate can never skip that check', () => {
    expect(filters(job('build'))).toEqual([
      'worker/src/__tests__/ci-workflow.test.ts',
    ]);
  });

  it('the gate, its outputs, and the module jobs agree', () => {
    expect(testJobs.map((j) => j.key.slice('test-'.length)).sort()).toEqual(
      [...modules].sort()
    );
    for (const m of modules) {
      expect(gate.outputs[`run-${m}`], m).toBe(
        `\${{ steps.relevance.outputs.run-${m} }}`
      );
      const j = job(`test-${m}`);
      expect(j.needs, m).toEqual(['build', 'gate']);
      expect(j.if, m).toBe(moduleIf(m));
      expect(filters(j).length, m).toBeGreaterThan(0);
    }
  });

  it('the gate is skipped on GitHub and runs on GitOrange', () => {
    const on = (server_url: string) =>
      evaluateCondition(gate.if, { github: { server_url } });
    expect(on('https://github.com')).toBe(false);
    expect(on('https://git.xyspace.dev')).toBe(true);
    expect(gate.needs).toEqual([]);
  });

  it("each module's if: runs on GitHub, follows the gate on GitOrange, and never runs after a failed build", () => {
    for (const m of modules) {
      const when = (
        gateResult: string,
        run: string | undefined,
        build = 'success'
      ) =>
        evaluateCondition(job(`test-${m}`).if, {
          needs: {
            build: { result: build, outputs: {} },
            gate: {
              result: gateResult,
              outputs: run === undefined ? {} : { [`run-${m}`]: run },
            },
          },
        });
      expect(when('skipped', undefined), `${m} on GitHub`).toBe(true);
      expect(when('success', 'true'), `${m} relevant`).toBe(true);
      expect(when('success', 'false'), `${m} irrelevant`).toBe(false);
      expect(when('failure', undefined), `${m} gate failed`).toBe(false);
      expect(when('skipped', undefined, 'failure'), `${m} build failed`).toBe(
        false
      );
    }
  });

  it("module jobs restore the commit's build, and build it on a miss", () => {
    const key = '${{ github.sha }}';
    const save = job('build').steps.find((s) =>
      s.uses?.startsWith('actions/cache@')
    );
    expect(save?.with.key).toBe(`build-${key}`);
    expect(save?.with.path.split('\n').filter(Boolean)).toEqual([
      'node_modules',
      'dist',
    ]);
    for (const j of testJobs) {
      const restore = j.steps.find((s) => s.uses?.startsWith('actions/cache@'));
      expect(restore?.id, j.key).toBe('build-cache');
      expect(restore?.with.key, j.key).toBe(`build-${key}`);
      const fallback = j.steps.find(
        (s) => s.name === 'Install and build (cache miss)'
      );
      expect(fallback?.if, j.key).toBe(
        "steps.build-cache.outputs.cache-hit != 'true'"
      );
      // Config is staged before anything builds or tests.
      const order = j.steps.map((s) => s.name ?? s.uses ?? '');
      expect(order.indexOf('Stage config'), j.key).toBeLessThan(
        order.indexOf('Install and build (cache miss)')
      );
    }
  });
});
```

## CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) builds and typechecks once (`build`), then runs the tests in one job per module (`test-stacking`, `test-review`, `test-merge`, `test-actions`, `test-mcp`, `test-git`, `test-core`, `test-ui`), in parallel, from the build's cache. On GitOrange a `gate` job asks [`gitorange/relevance@v1`](ci-relevance.md) which modules a change can affect and skips the rest; on GitHub the gate is skipped and every module runs.

Every test file belongs to exactly one module. When you add a test file, add it to the `yarn test` line of its module's job; `worker/src/__tests__/ci-workflow.test.ts`, which `build` always runs, fails until you do. A new module needs a `test-<name>` job, a line in the gate's `modules`, and a `run-<name>` gate output.
