# Deterministic install Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `yarn gitorange install [--plan] [--resume]` and `yarn gitorange status` set up a GitOrange instance on
Cloudflare deterministically, ending with a one-time setup code that the welcome page requires.

**Architecture:** A Node CLI in `scripts/gitorange/`: pure modules (names, plan, config generation, state transitions)
plus two ports — a typed Cloudflare REST client (`fetch`) and a process runner (wrangler, docker, git) — that tests
replace with fakes. The Worker gains an `install_state` D1 table, `GET /.well-known/gitorange`, two vars and an
optional `SETUP_CODE_HASH` secret that gates `/api/setup`.

**Tech Stack:** Node 22 (type stripping: `node scripts/gitorange/cli.ts`), `node:util` `parseArgs`, `@clack/prompts`,
`jsonc-parser`, Vitest (Node environment) for the CLI; Hono/Zod-OpenAPI, Drizzle/D1, React for the Worker side.

**Spec:** `docs/superpowers/specs/2026-10-16-deterministic-install-design.md` — read it first; section refs (§n) below
point into it.

## Global Constraints

- Default installation name `gitorange`; names: worker `<n>`, D1 `<n>-db`, R2 `<n>-lfs` / `<n>-actions-logs` /
  `<n>-actions-cache`, Workflows `<n>-actions-run` / `<n>-merge-resolution`, Artifacts namespace `<n>`.
- Name validation: lowercase slug, 3–30 chars, `[a-z0-9-]`, no leading/trailing hyphen.
- `installationId = <n>-` + first 12 hex of `sha256(accountId, n, hostname)`; `hostname` = the custom hostname or the
  literal `workers.dev`.
- Plan digest = first 12 hex of `sha256` over the installation id and the ordered `{action, kind, name}` list.
- Ownership: worker var `GITORANGE_INSTALLATION` = JSON `{installationId, ownershipNonce}`; R2 object
  `.gitorange/ownership.json` = `{installationId, ownershipNonce, key}`; D1 row in `install_state`.
- Actions cache lifecycle rule id `expire-7d`, prefix `actions-cache/`, 7 days.
- State file `.gitorange/<installationId>.json`, mode 0600, atomic write; lock `.gitorange/<installationId>.lock`.
- Secrets never in argv, the state file, plan output, or logs. Secrets reach wrangler only via a 0600 temp file and
  `wrangler deploy --secrets-file`, deleted afterwards.
- `BETTER_AUTH_SECRET` generated only when `wrangler secret list` lacks it; never regenerated.
- Without a terminal, any apply needs `--yes`; `--plan` never does.
- Final plan line: `No Cloudflare resource or local file was changed.`
- Existing-but-not-ours stop message: `` `<name>` already exists and was not created by this installation. Nothing was changed. ``
- Generated `wrangler.jsonc` first line starts with `// Generated by yarn gitorange install (`; never overwrite a
  `wrangler.jsonc` without it.
- Worker: when `SETUP_CODE_HASH` is unset, `/api/setup` behaves exactly as today.
- Project rules (CLAUDE.md): yarn only; migrations via `yarn db:generate` (never hand-written); new binding/var/secret
  → `wrangler.jsonc.example` (top level and `env.dev`), `wrangler.jsonc.ci`, `wrangler.test.jsonc` if tests need it,
  `docs/configuration.md`, then `yarn cf-typegen`; done = `yarn test`, `yarn typecheck`, `yarn format`.

## Review Focus

1. A hand-written `wrangler.jsonc` already in the checkout (every existing deployer has one) → refuse, change nothing,
   say how to move it aside. Pinned in Task 8.
2. A run killed between "create" and "record resource" → the rerun finds the same-name resource and accepts it only
   through the ownership marker (or, for D1 before migrations, an intent plus an empty database). Pinned in Task 10.
3. Custom-domain certificate still issuing at verify → `/.well-known/gitorange` 5xx/TLS errors retried for ~60 s, then
   a failure naming the URL, not a crash. Pinned in Task 10.
4. Non-interactive shell (CI, Claude's Bash tool) without `--yes` → exits non-zero naming `--yes`, before any write.
   Pinned in Task 11.
5. A stale lock left by a crashed run (pid gone, same host) → reclaimed; a live one → "another install is running".
   Pinned in Task 4.
