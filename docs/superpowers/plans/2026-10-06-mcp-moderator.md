# MCP Moderator Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can mark one or more of their connected MCP apps as a **moderator**; a moderator connection can
approve agent findings that need a person, dismiss agent change requests, and approve pull requests over MCP —
through the exact code paths the web UI uses — with each decision recorded as made by that user **via** that app.
No other MCP connection can.

**Architecture:** A new app table `mcp_moderators` (user, OAuth client) is toggled from Settings → MCP server →
Connected apps by session-only routes. `POST /mcp` reads the row fresh on every `initialize`, `tools/list` and
moderator `tools/call` (never cached), lists the three moderator tools only to a moderator connection, and refuses
them from any other before a handler runs. The tools call the web's own `decideFlag` and `approvePull`, which gain
options for the audit name (`via`), the finding kind, and the head commit the moderator looked at;
`pr_review_flags.approved_via` and `pr_approvals.via` (plus the `approved` event's `via`) record the app's name, and
the Reviewers box and timeline show "@user via <app>".

**Tech Stack:** Cloudflare Workers, Hono, Drizzle/D1, better-auth (`@better-auth/oauth-provider` + `jwt()`), the
hand-rolled JSON-RPC MCP server in `worker/src/mcp/`, React + TanStack Query + Primer CSS, Vitest
(`@cloudflare/vitest-pool-workers`, real D1, Artifacts fake).

**Spec:** `docs/superpowers/specs/2026-10-06-mcp-moderator-design.md` — sections 1 (marking an app), 2 (moderator
MCP tools), 3 (audit), 4 (testing). Read it with this plan; the Decisions below record where the real code differs
from the spec's assumptions.

## Global Constraints

- A user can mark one or more of their connected MCP apps as a **moderator**. A moderator connection can approve agent findings, dismiss agent change requests, and approve pull requests — the decisions a person makes in the web UI — with every decision recorded as made by that user **via** that app. Other MCP connections can't.
- Non-goals: no moderator built into GitOrange; no new merge paths (merging stays `gitorange_merge_pull_request` / auto-merge through the unchanged gate); a moderator is not restricted from pull requests the same app opened.
- Stored in a new app table `mcp_moderators` (`user_id`, `client_id`, `created_at`; primary key (user, client); deleted with the user). better-auth's generated consent/client tables are not changed.
- The toggle routes are session only — never over MCP.
- Disconnecting an app (revoking consent) also removes its moderator row. The moderator check runs on every MCP call, so turning it off, or disconnecting, takes effect immediately.
- A moderator acts with the user's own permissions: each tool still requires `perms.write` on the repository.
- Moderator tools are listed in `tools/list` and callable only when the MCP session's (user, client) has a moderator row. A direct call from another connection is refused.
- `gitorange_approve_review_finding { repository, number, finding_id, head_sha }` — approve an agent finding that needs a person (`kind = needs_person`). Same effect as the web approve.
- `gitorange_dismiss_change_request { repository, number, finding_id, head_sha }` — dismiss an agent's change request (`kind = change_requested`). Same effect as the web dismiss.
- `gitorange_approve_pull_request { repository, number, head_sha }` — approve the pull request's current head. Same effect as a person's Approve: satisfies review when no agent was requested, and overrides needs-a-person findings and failed agent reviews, but not open change requests.
- Every tool requires `head_sha` (the commit the moderator looked at); a mismatch with the pull request's current head answers an error ("The pull request has new commits since you looked") and records nothing.
- `gitorange_request_changes_on_review_flag` stays available to every MCP client, as today. Reading findings needs no new tool (`gitorange_get_pull_request` returns them).
- `pr_review_flags` gains `approved_via` (text, nullable): the app's client name for decisions made over MCP. `pr_approvals` gains `via` (text, nullable) likewise; the `approved` timeline event records `via`. Web decisions leave `via` null.
- The web UI shows "@user via <app name>" wherever an approval or dismissal is shown.
- Migration generated by `yarn db:generate`; additive only. Never hand-write migrations; never hand-edit `worker/src/db/auth.schema.ts`.
- Always `yarn` (never `npm`/`npx`).
- Tests live in `worker/src/__tests__/`, run against real D1 with the Artifacts fake; never mock `env.DB`. Every new test file is added to a job in `.github/workflows/ci.yml` (`ci-workflow.test.ts` enforces it; `src/lib/` is listed as a directory, so new `src/lib/*.test.ts` files are covered already).
- Definition of done: `yarn test` passes, `yarn typecheck` clean, `yarn format` run.
- Commits end with:
  ```
  Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>
  ```

## Decisions (made while planning)

1. **Routes and page names follow the real code, not the spec's guesses.** There is no `GET /api/me/mcp-apps` or
   "Settings → Connected apps" page. The existing page is **Settings → MCP server** (`src/pages/SettingsMcp.tsx`)
   with a **Connected apps** section fed by `GET /api/mcp/connections` (`mcpApiRouter` in
   `worker/src/mcp/index.ts`, mounted at `/api/mcp` behind `requireAuth`), and disconnecting is
   `DELETE /api/mcp/connections/:clientId`. So: the list gains `moderator: boolean`; the toggle is
   `PUT` / `DELETE /api/mcp/connections/:clientId/moderator`. The refusal message names the real place:
   "This connected app isn't a moderator — turn it on in Settings → MCP server → Connected apps."
2. **Session-only is structural, and a test pins it.** The app-wide middleware in `worker/src/index.ts` sets
   `c.get('user')` only from `auth.api.getSession` (cookies; better-auth's `bearer()` plugin is not installed), and
   skips `/mcp` entirely. An MCP JWT sent as `Authorization: Bearer` to `/api/mcp/...` therefore has no user and
   `requireAuth` answers 401. No new guard is added; Task 1's test proves a JWT can't toggle (on or off).
3. **The check runs on every call; nothing is cached.** `moderatorFor(db, userId, clientId)` (one D1 read joined to
   `oauth_clients` for the name) runs in `initialize` (one extra sentence of instructions), `tools/list`, and
   every `tools/call` of a moderator tool, before the handler. The handlers re-check `ctx.moderator` (defence in
   depth) and take `via` from it. `getMcpSession` already re-checks the consent row per call, so disconnecting
   answers 401 on the next request.
4. **One implementation of each decision.** `decideFlag` (`review/flags.ts`) gains
   `opts: { via?, kind?, expectedHead? }`; `approvePull` (`review/approvals.ts`) gains `opts.via`. The web routes
   pass none of the new options and behave exactly as today. The MCP tools call these same functions — no second
   UPDATE/INSERT anywhere — then `publishChange` like the existing MCP flag tool (the web gets that ping from its
   `pingAfterChange` middleware).
5. **What "the head the moderator looked at" means for a finding.** `expectedHead` refuses (409, nothing written)
   unless the pull request's current head (`git.resolve(pr.headRef)`) **and** the head the finding was raised on
   (`pr_classifications.head_sha` of its review) both equal `head_sha`. A finding from an earlier commit's review
   can't be decided against a newer head. `head_sha` must be the full SHA (`gitorange_get_pull_request`'s
   `head_sha`); an abbreviated one is a mismatch. For pull requests `approvePull`'s existing `expectedHead` check
   (409) does the same; the tool always passes it (the web's is optional, the tool's is required).
6. **`via` is the app's registered name at decision time** — `oauth_clients.name` (trimmed; `"Unnamed app"` when
   empty), the name the user saw on the consent screen and in Connected apps. It is self-declared by the client at
   dynamic registration, so it is a label, not an identity; it is stored as text and React escapes it. It is copied,
   so renaming or deleting the client later doesn't rewrite history.
7. **Kinds.** `opts.kind` makes `decideFlag` refuse (400) a finding of the other kind:
   approve-finding takes only `needs_person`, dismiss only `change_requested`. The web's approve route keeps
   accepting both (its "Dismiss" button is the same route).
8. **Deciding twice keeps the first decision.** Unchanged semantics: a finding already approved/dismissed (on the web
   or by another app) stays as it was, `approved_via` included; a pull request the user already approved stays
   approved by the first approval (`ON CONFLICT DO NOTHING`), with its `via` and a single `approved` event. The tool
   answers success in both cases (the outcome the moderator wanted holds).
9. **The moderator row.** `PUT` requires the user's own consent row for that client (404 otherwise, so no one can
   mark another user's or an unknown client); it is idempotent. `DELETE` is idempotent and only touches the
   caller's rows. Foreign keys: `user_id → users.id` and `client_id → oauth_clients.client_id`, both
   `ON DELETE CASCADE`. Disconnecting deletes the row in the same `db.batch` as the consent and tokens, so
   re-authorizing the same client starts as a non-moderator.
10. **Tool lists.** Non-moderator connections see exactly today's 13 tools. `GET /api/mcp` keeps `tools` (those 13)
    and adds `moderatorTools` (the three), shown on the settings page under "Moderator tools".
11. **Where "via" shows.** The PR Reviewers box (each finding's "Approved/Dismissed by", and the people who approved
    the commit) and the timeline's `approved` event. Finding decisions have no timeline event today and this plan
    doesn't add one. The Approvals page lists only undecided items, so it never shows an approver and needs no
    change (spec adaptation). MCP's `gitorange_get_pull_request` is unchanged.
12. **Test helpers move.** `mcp.test.ts`'s OAuth helpers (`ORIGIN`, `REDIRECT`, `b64url`, `pkce`, `raw`, `rpc`,
    `register`, `authorize`, `connect`, `ToolResult`, `tool`) move verbatim to `worker/src/__tests__/helpers/mcp.ts`
    so the new test file can connect apps; `connect` gains an optional client name.

## Review Focus

1. **The user already approved the pull request on the web, then the moderator approves it:** one approval, one
   `approved` event, `via` stays null, and the tool still reports success. → Task 2 test "keeps the first approval
   of a commit, and its via".
2. **A finding from an earlier commit's review, decided with the current head's SHA:** refused, nothing recorded
   (it was raised on code that's no longer the head). → Task 2 test "refuses a head the decider didn't see, and a
   finding raised on an earlier head".
3. **Toggling an app the user never connected (someone else's client id, or a made-up one):** 404 and no row; the
   other user's app doesn't become a moderator. → Task 1 test "refuses an app the user hasn't connected".
4. **A finding already decided on the web, then approved by the moderator:** the first decision stands
   (`approved_by`, `approved_at`, `approved_via` null). → Task 2 test "keeps the first decision on a finding".
5. **An abbreviated `head_sha` (the 7-character SHA a person would copy from the UI):** treated as a mismatch,
   nothing recorded. → Task 2 test "refuses a head the decider didn't see…" and Task 3 test "records nothing when
   the pull request has moved since the moderator looked".

```ts
/** OAuth 2.1 + MCP helpers: register a client, authorize it for a signed-in user, call /mcp. */
import { expect } from 'vitest';
import { app } from '../../index';
import { call, type TestEnv } from './app';

export const ORIGIN = 'http://test.local';
export const REDIRECT = 'http://127.0.0.1:33418/callback';

export function b64url(bytes: Uint8Array) {
  return btoa(String.fromCharCode(...bytes))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=+$/, '');
}

export async function pkce() {
  const verifier = b64url(crypto.getRandomValues(new Uint8Array(32)));
  const digest = await crypto.subtle.digest(
    'SHA-256',
    new TextEncoder().encode(verifier)
  );
  return { verifier, challenge: b64url(new Uint8Array(digest)) };
}

/** A raw request through the app, without the JSON/Origin defaults of `call`. */
export function raw(t: TestEnv, path: string, init: RequestInit = {}) {
  return app.fetch(new Request(`${ORIGIN}${path}`, init), t.env, t.ctx);
}

export async function rpc(
  t: TestEnv,
  token: string | null,
  method: string,
  params?: unknown,
  id: number | undefined = 1
) {
  return raw(t, '/mcp', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Accept: 'application/json, text/event-stream',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    },
    body: JSON.stringify({ jsonrpc: '2.0', id, method, params }),
  });
}

/** Registers a public client the way MCP clients do (RFC 7591, no credentials). */
export async function register(t: TestEnv, name = 'Claude Code') {
  const meta = (await (
    await raw(t, '/.well-known/oauth-authorization-server/api/auth')
  ).json()) as { registration_endpoint: string };
  const res = await raw(t, new URL(meta.registration_endpoint).pathname, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      client_name: name,
      redirect_uris: [REDIRECT],
      grant_types: ['authorization_code', 'refresh_token'],
      response_types: ['code'],
      token_endpoint_auth_method: 'none',
    }),
  });
  expect(res.status).toBe(201);
  return ((await res.json()) as { client_id: string }).client_id;
}

/** Runs authorize → consent → token for a signed-in user. Returns the token response. */
export async function authorize(t: TestEnv, cookie: string, clientId: string) {
  const { verifier, challenge } = await pkce();
  const params = new URLSearchParams({
    response_type: 'code',
    client_id: clientId,
    redirect_uri: REDIRECT,
    scope: 'openid profile email offline_access',
    code_challenge: challenge,
    code_challenge_method: 'S256',
    state: 'xyz',
    resource: `${ORIGIN}/mcp`,
  });
  const auth = await raw(t, `/api/auth/oauth2/authorize?${params}`, {
    headers: { Cookie: cookie },
    redirect: 'manual',
  });
  expect(auth.status).toBe(302);
  const consentUrl = new URL(auth.headers.get('Location')!, ORIGIN);
  expect(consentUrl.pathname).toBe('/oauth/consent');

  // As the consent page does: post the decision with its signed query.
  const consent = await call(t, '/api/auth/oauth2/consent', {
    cookie,
    json: { accept: true, oauth_query: consentUrl.search.slice(1) },
  });
  expect(consent.status).toBe(200);
  const { url } = (await consent.json()) as { url: string };
  const callback = new URL(url);
  expect(`${callback.origin}${callback.pathname}`).toBe(REDIRECT);
  expect(callback.searchParams.get('state')).toBe('xyz');

  const token = await raw(t, '/api/auth/oauth2/token', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams({
      grant_type: 'authorization_code',
      code: callback.searchParams.get('code')!,
      redirect_uri: REDIRECT,
      client_id: clientId,
      code_verifier: verifier,
      resource: `${ORIGIN}/mcp`,
    }),
  });
  expect(token.status).toBe(200);
  return (await token.json()) as {
    access_token: string;
    refresh_token?: string;
    token_type: string;
  };
}

export async function connect(
  t: TestEnv,
  cookie: string,
  name = 'Claude Code'
) {
  const clientId = await register(t, name);
  const tokens = await authorize(t, cookie, clientId);
  return { clientId, ...tokens };
}

export type ToolResult = {
  isError?: boolean;
  content: { type: string; text: string }[];
};
export async function tool(
  t: TestEnv,
  token: string,
  name: string,
  args: Record<string, unknown> = {}
) {
  const res = await rpc(t, token, 'tools/call', { name, arguments: args });
  expect(res.status).toBe(200);
  return ((await res.json()) as { result: ToolResult }).result;
}
```

Create `worker/src/__tests__/mcp-moderator.test.ts`:

```ts
import { describe, expect, it } from 'vitest';
import {
  addMember,
  bootstrapAdmin,
  call,
  makeEnv,
  type TestEnv,
} from './helpers/app';
import { authorize, connect } from './helpers/mcp';

type App = { clientId: string; name: string; moderator: boolean };
const apps = async (t: TestEnv, cookie: string) =>
  (await (await call(t, '/api/mcp/connections', { cookie })).json()) as App[];
const moderatorPath = (clientId: string) =>
  `/api/mcp/connections/${encodeURIComponent(clientId)}/moderator`;
const setModerator = (
  t: TestEnv,
  cookie: string,
  clientId: string,
  on: boolean
) =>
  call(t, moderatorPath(clientId), { cookie, method: on ? 'PUT' : 'DELETE' });
const moderatorRows = async (t: TestEnv) =>
  (
    await t.env.DB.prepare(
      'SELECT user_id, client_id FROM mcp_moderators ORDER BY client_id'
    ).all<{ user_id: string; client_id: string }>()
  ).results;

describe('marking a connected app as a moderator', () => {
  it('lists each app with its moderator flag, and turns it on and off', async () => {
    const t = makeEnv();
    const admin = await bootstrapAdmin(t);
    const mod = await connect(t, admin, 'Claude Mod');
    const coder = await connect(t, admin, 'Claude Code');
    expect(
      (await apps(t, admin)).map((a) => [a.name, a.moderator]).sort()
    ).toEqual([
      ['Claude Code', false],
      ['Claude Mod', false],
    ]);

    const on = await setModerator(t, admin, mod.clientId, true);
    expect(on.status).toBe(200);
    expect(await on.json()).toEqual({ ok: true, moderator: true });
    // Idempotent.
    expect((await setModerator(t, admin, mod.clientId, true)).status).toBe(200);
    const listed = await apps(t, admin);
    expect(listed.find((a) => a.clientId === mod.clientId)?.moderator).toBe(
      true
    );
    expect(listed.find((a) => a.clientId === coder.clientId)?.moderator).toBe(
      false
    );
    expect(await moderatorRows(t)).toHaveLength(1);

    const off = await setModerator(t, admin, mod.clientId, false);
    expect(off.status).toBe(200);
    expect(await off.json()).toEqual({ ok: true, moderator: false });
    expect(await moderatorRows(t)).toEqual([]);
  });

  it("refuses an app the user hasn't connected", async () => {
    const t = makeEnv();
    const admin = await bootstrapAdmin(t);
    const bob = await addMember(t, admin, 'bob');
    const bobs = await connect(t, bob, 'Bob Mod');
    // Someone else's app, and an id nobody registered.
    expect((await setModerator(t, admin, bobs.clientId, true)).status).toBe(
      404
    );
    expect((await setModerator(t, admin, 'no-such-client', true)).status).toBe(
      404
    );
    expect(await moderatorRows(t)).toEqual([]);
    expect((await apps(t, bob))[0].moderator).toBe(false);
  });

  it('takes the setting only from a signed-in session, never an MCP token', async () => {
    const t = makeEnv();
    const admin = await bootstrapAdmin(t);
    const mod = await connect(t, admin, 'Claude Mod');
    const bearer = { Authorization: `Bearer ${mod.access_token}` };
    const put = await call(t, moderatorPath(mod.clientId), {
      method: 'PUT',
      headers: bearer,
    });
    expect(put.status).toBe(401);
    expect(await moderatorRows(t)).toEqual([]);
    // Nor can a token turn it off once the user turned it on.
    await setModerator(t, admin, mod.clientId, true);
    const del = await call(t, moderatorPath(mod.clientId), {
      method: 'DELETE',
      headers: bearer,
    });
    expect(del.status).toBe(401);
    expect(await moderatorRows(t)).toHaveLength(1);
    // Nor list the user's apps.
    expect(
      (await call(t, '/api/mcp/connections', { headers: bearer })).status
    ).toBe(401);
  });

  it('forgets the setting when the app is disconnected', async () => {
    const t = makeEnv();
    const admin = await bootstrapAdmin(t);
    const mod = await connect(t, admin, 'Claude Mod');
    await setModerator(t, admin, mod.clientId, true);
    const res = await call(
      t,
      `/api/mcp/connections/${encodeURIComponent(mod.clientId)}`,
      { cookie: admin, method: 'DELETE' }
    );
    expect(res.status).toBe(200);
    expect(await moderatorRows(t)).toEqual([]);
    // Reconnecting the same app starts over as an ordinary connection.
    await authorize(t, admin, mod.clientId);
    expect((await apps(t, admin))[0]).toMatchObject({
      clientId: mod.clientId,
      moderator: false,
    });
  });
});
```

```ts
/**
 * The user's app as a moderator, or null. Read fresh on every MCP call that needs it — never cache it — so turning
 * it off (or disconnecting) takes effect on the next call. `name` is the app's registered name, as on the consent
 * screen and in Connected apps.
 */
export async function moderatorFor(
  db: DrizzleDB,
  userId: string,
  clientId: string
): Promise<Moderator | null> {
  const row = await db
    .select({ name: oauthClients.name })
    .from(mcpModerators)
    .innerJoin(oauthClients, eq(oauthClients.clientId, mcpModerators.clientId))
    .where(
      and(
        eq(mcpModerators.userId, userId),
        eq(mcpModerators.clientId, clientId)
      )
    )
    .get();
  return row ? { clientId, name: row.name?.trim() || 'Unnamed app' } : null;
}

/** The client ids of the user's moderator apps (for the Connected apps list). */
export async function moderatorClientIds(
  db: DrizzleDB,
  userId: string
): Promise<Set<string>> {
  const rows = await db
    .select({ clientId: mcpModerators.clientId })
    .from(mcpModerators)
    .where(eq(mcpModerators.userId, userId))
    .all();
  return new Set(rows.map((r) => r.clientId));
}

/**
 * Turns moderator on or off for one of the user's connected apps. Turning it on needs the user's own consent for
 * that app (false otherwise: never someone else's app or an unknown id); both directions are idempotent.
 */
export async function setModerator(
  db: DrizzleDB,
  userId: string,
  clientId: string,
  on: boolean
): Promise<boolean> {
  const mine = and(
    eq(mcpModerators.userId, userId),
    eq(mcpModerators.clientId, clientId)
  );
  if (!on) {
    await db.delete(mcpModerators).where(mine);
    return true;
  }
  const consent = await db
    .select({ id: oauthConsents.id })
    .from(oauthConsents)
    .where(
      and(
        eq(oauthConsents.userId, userId),
        eq(oauthConsents.clientId, clientId)
      )
    )
    .get();
  if (!consent) return false;
  await db
    .insert(mcpModerators)
    .values({ userId, clientId, createdAt: new Date() })
    .onConflictDoNothing();
  return true;
}
```

```ts
/** index.ts refuses these before the handler for a non-moderator; this is the second lock. */
function moderatorOf(ctx: ToolContext): Moderator {
  if (!ctx.moderator) throw new McpToolError(NOT_MODERATOR);
  return ctx.moderator;
}

const headShaProp = {
  type: 'string',
  description:
    'The full head commit SHA you reviewed (head_sha from gitorange_get_pull_request). If the pull request has ' +
    'new commits since, nothing is recorded: look again.',
};
const findingIdProp = {
  type: 'string',
  description:
    "The finding's id, from gitorange_get_pull_request's reviewers[].findings.",
};

/** The repository, pull request and head SHA a moderator tool acts on, after the same checks as the web UI. */
async function moderatedPull(
  args: Record<string, unknown>,
  ctx: ToolContext,
  verb: string
) {
  const moderator = moderatorOf(ctx);
  const { repo, fullName, perms, git } = await repoFor(ctx, args);
  // The same permission as the web's approve and dismiss: merge (push) access.
  if (!perms.write)
    throw new McpToolError(
      `You don't have permission to ${verb} in ${fullName}.`
    );
  const pr = await pullFor(ctx, repo.id, fullName, prNumber(args));
  const headSha = str(args, 'head_sha', true).trim();
  return { moderator, repo, fullName, git, pr, headSha };
}

/** Approves (needs_person) or dismisses (change_requested) one finding through the web's `decideFlag`. */
async function decideFinding(
  args: Record<string, unknown>,
  ctx: ToolContext,
  kind: FlagKind
) {
  const { moderator, repo, fullName, git, pr, headSha } = await moderatedPull(
    args,
    ctx,
    kind === 'needs_person' ? 'approve findings' : 'dismiss change requests'
  );
  const findingId = str(args, 'finding_id', true).trim();
  const result = await decideFlag(
    ctx.env,
    ctx.db,
    pr,
    findingId,
    ctx.user.id,
    { kind: 'approve' },
    ctx.after,
    { via: moderator.name, kind, expectedHead: { sha: headSha, git } }
  );
  if (!result.ok)
    throw new McpToolError(
      result.status === 404
        ? `#${pr.number} has no finding ${findingId}. Call gitorange_get_pull_request to see its findings.`
        : result.error
    );
  ctx.after(publishChange(ctx.env, repo.id, { approvals: true }));
  return pullUrl(ctx, fullName, pr.number);
}
```
